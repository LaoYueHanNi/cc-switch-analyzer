# CC-Switch 使用分析器 — 产品需求文档 (PRD)

> 版本: 1.0 | 日期: 2026-05-02
>
> 本文档基于现有产品反向梳理，聚焦功能完整性与模块交互，不涉及技术实现细节。

---

## 一、产品概述

### 1.1 产品定位

CC-Switch 使用分析器是一款桌面端数据分析工具，面向使用 CC-Switch 代理服务的用户，帮助其掌握 LLM API 的使用情况、成本消耗和优化空间。

### 1.2 核心价值

- **成本透明**：将 API 调用数据转化为可理解的费用分析，按模型/供应商/时间维度展示
- **用量监控**：实时监控 Token 消耗趋势，及时发现异常
- **定价管理**：支持自定义定价覆盖和时间定价策略，灵活适配不同计费场景
- **数据驱动决策**：提供模型成本对比、缓存效率分析等工具，辅助用户优化 API 使用策略

### 1.3 数据来源

本产品本身不产生数据，依赖外部数据源：

| 数据源 | 说明 | 读写权限 |
|--------|------|----------|
| CC-Switch 代理数据库 | 代理服务自动生成的 SQLite 文件，包含请求日志、供应商信息、基础模型定价 | 只读 |
| 应用自有数据库 | 本地存储的用户配置数据，包括定价覆盖、时间定价、汇率设置、应用设置 | 读写 |

### 1.4 数据模型

#### 1.4.1 请求数据

每条 API 请求记录包含以下维度：

| 维度 | 说明 |
|------|------|
| 时间戳 | 请求发生时间（Unix 秒） |
| 供应商标识 | 请求路由到的 API 供应商 |
| 模型标识 | 使用的 LLM 模型名称 |
| 状态码 | HTTP 响应状态码（200=成功） |
| Token 用量 | 四个维度：输入、输出、缓存读取、缓存写入 |
| 费用 | 各维度的费用（原始为 USD） |
| 延迟 | 请求响应时间（毫秒） |

#### 1.4.2 供应商数据

| 维度 | 说明 |
|------|------|
| 供应商 ID | 唯一标识 |
| 供应商名称 | 显示名称 |
| 应用类型 | 供应商类别 |

#### 1.4.3 模型定价数据

| 维度 | 说明 |
|------|------|
| 模型 ID | 唯一标识（同时作为显示名称的备选） |
| 显示名称 | 用户友好的模型名称 |
| 输入单价 | 每百万 Token 的输入费用（USD） |
| 输出单价 | 每百万 Token 的输出费用（USD） |
| 缓存读取单价 | 每百万 Token 的缓存读取费用（USD） |
| 缓存写入单价 | 每百万 Token 的缓存写入费用（USD） |

#### 1.4.4 费用计算公式

```
总费用 = (输入Token × 输入单价 + 输出Token × 输出单价
       + 缓存读取Token × 缓存读取单价 + 缓存写入Token × 缓存写入单价) / 1,000,000
```

所有费用在展示前统一通过汇率转换为人民币（CNY）。

## 七、模块一：按模型统计

### 7.1 整体布局

采用卡片流布局（自动换行），每张卡片代表一个模型。卡片按请求数降序排列。

### 7.2 模型卡片内容

每张模型卡片展示以下信息：

| 区域 | 内容 | 说明 |
|------|------|------|
| 模型名称 | 粗体显示 | 取自模型的显示名称 |
| 总费用 | 大号红色文字（如 ¥12.34） | 可点击，触发费用对比功能 |
| 总 Token 数 | 大号青色文字 | K/M 格式化 |
| 单次请求费用 | 小字（如 每次请求 ¥0.001234） | 总费用 / 请求数 |
| 缓存命中率 | 百分比 | 缓存读取 / (输入 + 缓存读取 + 缓存写入) |
| 平均缓存时长 | 可点击 | 点击弹出缓存窗口详情 |

### 7.3 费用分解网格

每张卡片底部显示四行费用分解：

| 维度 | 颜色标识 | 每行显示 |
|------|----------|----------|
| 输入 | 紫色圆点 | Token 数量 + 费用（¥） + 每百万单价 |
| 输出 | 橙色圆点 | Token 数量 + 费用（¥） + 每百万单价 |
| 缓存读取 | 蓝色圆点 | Token 数量 + 费用（¥） + 每百万单价 |
| 缓存写入 | 深橙色圆点 | Token 数量 + 费用（¥） + 每百万单价 |

### 7.4 特殊状态

| 状态 | 表现 |
|------|------|
| 无定价数据 | 显示"暂无定价数据"提示 + "设置定价"按钮，点击跳转到定价计算器并进入编辑模式 |
| 存在时间定价规则 | 显示时钟图标标记 + "包含时段定价"，单价列显示时钟图标代替数字 |

### 7.5 交互功能一：模型费用对比

**触发方式：** 点击卡片上的总费用文字。

**交互流程：**

1. 弹出模型选择器（可搜索的下拉列表，列出所有其他模型）
2. 用户输入关键词过滤，选择目标模型
3. 卡片切换为对比视图，展示：
   - 按目标模型定价计算的总费用
   - 费用差异百分比（如 +15.3% 或 -8.7%）
   - 四个维度的费用对比行（蓝色高亮）
4. 提供"恢复"按钮，返回原始视图

**业务含义：** 帮助用户评估"如果将当前模型的 Token 用量换算到另一个模型，费用会如何变化"，辅助模型选择决策。

### 7.6 交互功能二：缓存窗口详情

**触发方式：** 点击平均缓存时长文字。

**展示内容：** 弹出最近 10 个缓存命中窗口列表

| 列 | 说明 |
|----|------|
| 开始时间 | 缓存窗口的起始时间 |
| 结束时间 | 缓存窗口的结束时间 |
| 持续时长 | 格式化显示（如 5分钟、1小时30分钟） |
| 命中次数 | 窗口内的请求数 |

**数据范围：** 仅统计最近 30 天。

**缓存窗口定义：** 从出现缓存读取 Token > 0 的请求开始，到连续不再有缓存读取为止，视为一个缓存窗口。

## 八、模块二：按供应商统计

### 8.1 整体布局

采用卡片流布局（自动换行），每张卡片代表一个供应商。卡片按请求数降序排列。

### 8.2 供应商卡片内容

| 区域 | 内容 | 说明 |
|------|------|------|
| 供应商名称 | 粗体显示 | 关联供应商表获取显示名称，无则显示原始 ID |
| 总费用 | 大号红色文字 | 由该供应商下各模型的 Token 用量 × 模型定价累加 |
| 请求数 | 如 "请求: 1234" | 该供应商的请求总数 |

### 8.3 费用计算逻辑

供应商的费用 = 该供应商下所有请求按模型维度拆分后，分别乘以对应模型定价，再求和。

即：供应商费用需要通过"供应商-模型"的 Token 分布映射到模型定价来计算。

## 九、模块三：会话分析

### 9.1 排序选项

| 排序维度 | 说明 | 默认排序 |
|----------|------|----------|
| 费用 | 会话总费用 | 降序（默认） |
| Token 数量 | 会话总 Token 数 | 降序 |
| 请求数 | 会话请求数量 | 降序 |
| 上下文大小 | 会话中最大的 上下文 = 输入 + 缓存读取 | 降序 |
| 缓存命中率 | 会话的缓存命中比例 | 降序 |

### 9.2 会话定义

会话由外部数据源标识（session_id），同一会话包含多次 API 请求。本模块展示 Top 20 会话（按选定排序维度从 Top 50 中取前 20）。

### 9.3 会话卡片布局

每张会话卡片为水平全宽卡片，分为三个区域：

#### 区域一：概览信息（左侧固定宽度）

| 信息项 | 说明 |
|--------|------|
| 会话 ID | 显示短 ID（前缀部分），鼠标悬停显示完整 ID |
| 总费用 | 红色，按每次请求的时间戳匹配对应时刻的定价计算 |
| 总 Token 数 | 青色 |
| 请求数和持续时长 | 如 "15 次请求, 持续 5分钟" |
| 时间范围 | 如 "04/30 14:20 ~ 15:30" |
| 上下文大小 | 会话中最大的 输入+缓存读取 值，K/M 格式化 |
| 缓存命中率 | 百分比 |

#### 区域二：请求密度热力图（中间固定宽度）

| 元素 | 说明 |
|------|------|
| 面积图 | 将会话内所有请求时间戳分为 32 个时间桶，绘制密度曲线 |
| 渐变填充 | 红色渐变填充 |
| 时间标签 | 起止时间显示在图表两端 |
| 鼠标悬停提示 | 总请求数、峰值时间范围、峰值请求数 |

**业务含义：** 直观展示会话内请求的集中程度和时间分布，识别高密度使用时段。

#### 区域三：模型分解（右侧弹性宽度）

水平排列各模型块，每个模型块展示：

| 信息项 | 颜色 | 说明 |
|--------|------|------|
| 模型名称 | — | 截断 20 字符，悬停显示全名 |
| 输入 Token + 费用 | 紫色 | 该模型在该会话中的输入统计 |
| 输出 Token + 费用 | 橙色 | 同上 |
| 缓存读取 Token + 费用 | 蓝色 | 同上 |
| 缓存写入 Token + 费用 | 深橙色 | 同上 |
| 缓存命中率 | — | 百分比 |
| 模型总费用 | 红色 | 该模型在该会话中的费用合计 |

### 9.4 费用计算说明

会话的费用计算使用**时间感知定价**：每条请求按其发生时间戳匹配当时的定价规则（优先匹配时间定价，其次固定定价）。这确保了在使用限时折扣等策略时，会话费用的准确性。

## 十一、模块五：定价计算器

### 11.1 顶部工具栏

#### 第一行：模型筛选

| 控件 | 说明 |
|------|------|
| 搜索框 | 可输入的下拉列表，支持按模型 ID 或显示名称实时过滤 |
| 清除按钮 | 一键清空搜索关键词 |

#### 第二行：Token 输入与汇率

| 控件 | 默认值 | 说明 |
|------|--------|------|
| 输入 Token | 1K | 数值以千为单位，内部 ×1000 |
| 缓存读取 Token | 70K | 同上 |
| 输出 Token | 1K | 同上 |
| 缓存写入 Token | 0K | 同上 |
| 汇率 | 7.0 | USD → CNY 汇率，修改后 500ms 防抖保存 |

**汇率修改的影响范围：** 修改汇率后触发全局定价刷新 → 所有 Tab 的费用数据重新计算。

**Token 输入的防抖机制：** 修改任意 Token 输入框后 200ms 自动重新计算所有卡片。

### 11.2 卡片分组

定价卡片分为两组：

| 分组 | 说明 | 默认状态 |
|------|------|----------|
| 已使用模型 | 在请求日志中出现过的模型 | 始终展开 |
| 未使用模型 | 有定价数据但无实际使用的模型 | 默认折叠，点击标题可展开/收起 |

卡片按计算出的费用降序排列（费用最高的在前）。

### 11.3 定价卡片内容

每张卡片展示：

| 区域 | 内容 | 说明 |
|------|------|------|
| 模型显示名称 | 标题 | — |
| 编辑按钮 | 操作入口 | 点击进入内联编辑模式 |
| 计算费用 | 大号红色文字（4 位小数） | 基于顶部 Token 输入量 × 定价单价 |
| 单价网格 | 4 行（输入/输出/缓存读取/缓存写入） | 每行显示维度名 + 每百万单价，带颜色标识 |
| 自定义标记 | 青色"自定义"标签 | 仅当该模型有用户覆盖定价时显示 |
| 时间定价规则 | 每条规则一行 | 显示时钟图标 + 标签（或日期范围）+ 编辑/删除按钮 |
| 添加时间定价按钮 | 卡片底部 | 点击弹出添加对话框 |

### 11.4 交互功能一：内联编辑定价

**触发：** 点击卡片上的"编辑"按钮。

**编辑模式展示：**

| 控件 | 说明 |
|------|------|
| 4 个单价输入框 | 预填当前定价（输入/输出/缓存读取/缓存写入） |
| 保存按钮 | 保存为用户覆盖定价，触发全局刷新 |
| 取消按钮 | 退出编辑模式，恢复显示模式 |
| 恢复默认按钮 | 仅在有覆盖定价时显示，删除覆盖恢复为基础定价 |

**保存后的影响范围：** 定价更新后，所有 Tab 的费用数据重新计算和刷新。

### 11.5 交互功能二：添加时间定价

**触发：** 点击卡片底部的"添加时间定价"按钮。

**对话框内容：**

| 字段 | 默认值 | 说明 |
|------|--------|------|
| 起始日期 | 今天 | 时间定价生效的起始日 |
| 结束日期 | 今天 + 7 天 | 时间定价生效的截止日 |
| 4 个单价输入框 | 预填当前定价 | 该时段内的特殊定价 |
| 标签 | 空白 | 如"限时折扣"等描述 |

**业务含义：** 支持限时优惠、活动定价等场景。在指定时间范围内的请求将使用该时段的定价计算费用。

### 11.6 交互功能三：编辑/删除时间定价

**编辑：** 点击规则行的"编辑"按钮，弹出与添加相同的对话框，预填已有数据。

**删除：** 点击规则行的"删除"按钮，删除该时间定价规则。

操作后触发全局刷新。

## 十二、定价系统（跨模块核心逻辑）

> 定价系统是本产品的核心数据引擎，影响所有 Tab 的费用计算。

### 12.1 定价数据层级（优先级从高到低）

```
时间定价规则（最高优先级）
  ↓ 无匹配时回退
用户固定覆盖
  ↓ 无覆盖时回退
基础定价 × 汇率（最低优先级）
```

### 12.2 定价解析规则

**时间感知定价查询（`getPricingAt` 模型, 时间戳）：**

1. 检查该模型是否有时间定价规则覆盖该时间戳（起始 ≤ 时间戳 ≤ 结束）
2. 有 → 使用时间定价的单价
3. 无 → 使用固定定价（优先用户覆盖，其次基础定价 × 汇率）

### 12.3 汇率机制

| 属性 | 说明 |
|------|------|
| 默认汇率 | 7.0 |
| 存储位置 | 应用自有数据库的设置表 |
| 修改入口 | 定价计算器 Tab 的汇率输入框 |
| 修改影响 | 修改后所有基础定价重新换算 → 所有 Tab 费用重算 |

### 12.4 汇率换算规则

- 基础定价来源于 CC-Switch 数据库，单位为 USD
- 展示和计算时统一使用 CNY：基础定价 × 汇率
- 用户覆盖和时间定价直接以 CNY 录入和存储，不再乘以汇率

### 12.5 各模块使用的定价模式

| 模块 | 定价模式 | 说明 |
|------|----------|------|
| 按模型 — 总览统计 | 固定定价 | 使用合并后的固定单价 |
| 按模型 — 费用分解 | 固定定价 | 同上 |
| 按供应商 | 固定定价 | 通过模型费用间接计算 |
| 会话分析 | **时间感知定价** | 每条请求按时间戳匹配定价 |
| 定价计算器 | 固定定价 | 用于模拟计算和编辑 |
| 实时 Token | 不涉及费用 | 仅展示 Token 数量 |

## 十三、模块间数据流与交互

### 13.1 数据流图

```
用户数据库 (.db)                    应用自有数据库 (pricing.db)
    │                                       │
    │  请求日志、供应商、基础定价             │  用户定价覆盖、时间定价、汇率
    ▼                                       ▼
┌──────────────────────────────────────────────┐
│              数据读取层                       │
│  读取请求日志 → 汇总统计                      │
│  读取基础定价 → 传入定价系统                   │
└───────────────┬──────────────────────────────┘
                │
                ▼
┌──────────────────────────────────────────────┐
│              定价计算引擎                      │
│  基础定价 × 汇率 → 合并用户覆盖 → 应用时间定价  │
└───────────────┬──────────────────────────────┘
                │
       ┌────────┼────────────────────────┐
       ▼        ▼                        ▼
  预计算结果    实时查询               定价计算器
  (一次遍历)   (10秒轮询)             (独立计算)
       │        │                        │
  ┌────┼────┐   │                   编辑定价/汇率
  ▼    ▼    ▼   ▼                        │
 模型  供应商 会话  实时                全局定价刷新
 Tab   Tab   Tab   Tab                       │
                                             ▼
                                    所有 Tab 重新计算费用
```

### 13.2 预计算机制

当用户触发查询（点击查询按钮或快捷日期按钮）时，系统执行**一次遍历**预计算以下结果：

| 预计算项 | 用途 |
|----------|------|
| 每个模型的总费用 + 四维费用分解 | 模型 Tab 展示 |
| 每天的总费用、请求数、Token 数、延迟 | 趋势分析 |
| 每个供应商的费用（通过模型-供应商映射） | 供应商 Tab 展示 |
| 每个模型的每日数据列表 | 模型详情下钻 |

这种预计算确保多个 Tab 共享同一份计算结果，避免重复计算。

### 13.3 操作影响范围矩阵

| 操作 | 模型 Tab | 供应商 Tab | 会话 Tab | 实时 Tab | 定价 Tab |
|------|---------|-----------|---------|---------|---------|
| 切换数据库 | ✓ 刷新 | ✓ 刷新 | ✓ 刷新 | ✓ 刷新 | ✓ 刷新 |
| 修改筛选条件 | ✓ 刷新 | ✓ 刷新 | ✗ | ✗ | ✗ |
| 修改定价覆盖 | ✓ 刷新 | ✓ 刷新 | ✓ 刷新 | ✗ | ✓ 刷新 |
| 修改汇率 | ✓ 刷新 | ✓ 刷新 | ✓ 刷新 | ✗ | ✓ 刷新 |
| 修改时间定价 | ✓ 刷新 | ✓ 刷新 | ✓ 刷新 | ✗ | ✓ 刷新 |
| 进入实时 Tab | ✗ | ✗ | ✗ | ✓ 开始轮询 | ✗ |
| 离开实时 Tab | ✗ | ✗ | ✗ | ✓ 停止轮询 | ✗ |

### 13.4 定价编辑的级联刷新

任何定价修改（固定覆盖、时间定价、汇率）都会触发完整的级联刷新：

```
保存定价修改
  → 更新应用自有数据库
  → 重新加载定价数据
  → 重新执行主查询
  → 预计算费用
  → 刷新当前可见 Tab
```

## 十五、数值格式化规则

### 15.1 数字格式化

| 数量级 | 显示格式 | 示例 |
|--------|----------|------|
| < 1,000 | 原始数字 | 856 |
| 1,000 ~ 999,999 | K 简写（1 位小数） | 12.3K |
| ≥ 1,000,000 | M 简写（1 位小数） | 1.5M |

### 15.2 费用格式化

- 前缀：¥
- 最少 2 位小数，最多 4 位小数
- 去除尾部多余的零
- 示例：¥12.34、¥0.0012、¥1,234.5

### 15.3 定价单价格式化

- 每百万 Token 的费用
- 最多 4 位小数，去除尾部零，保证至少 2 位
- 示例：0.50、3.00、0.0012

### 15.4 时长格式化

| 时长范围 | 格式 | 示例 |
|----------|------|------|
| < 60 秒 | Xs | 45s |
| 1 分钟 ~ 59 分钟 | Xm | 5m |
| ≥ 1 小时 | Xh Ym | 1h 30m |

## 十七、业务规则汇总

| 编号 | 规则 | 说明 |
|------|------|------|
| BR-01 | 用户数据库只读 | 应用不得修改用户提供的 CC-Switch 数据库的任何内容（包括索引、表结构等） |
| BR-02 | 费用统一人民币 | 所有费用展示和计算均以人民币为单位 |
| BR-03 | 定价覆盖优先 | 用户自定义定价优先于基础定价 |
| BR-04 | 时间定价最高优先 | 在时间范围内的请求使用时间定价，无论固定定价如何 |
| BR-05 | 汇率只影响基础定价 | 用户覆盖和时间定价以人民币直接存储，不受汇率变更影响 |
| BR-06 | 缓存窗口限 30 天 | 缓存分析仅统计最近 30 天数据 |
| BR-07 | 会话展示 Top 20 | 会话分析最多展示 20 条，从 Top 50 中选取 |
| BR-08 | 实时监控限 1 小时 | 实时 Token 图表固定展示最近 1 小时数据 |
| BR-09 | 全局刷新一致性 | 定价或汇率变更后，所有 Tab 费用数据同步刷新 |
| BR-10 | 防抖机制 | Token 输入 200ms 防抖，汇率输入 500ms 防抖，避免频繁计算 |
| BR-11 | 汇率默认值 | 汇率默认为 7.0，可修改并持久化 |
| BR-12 | 缓存命中率公式 | 缓存命中率 = 缓存读取 Token / (输入 Token + 缓存读取 Token + 缓存写入 Token) |
