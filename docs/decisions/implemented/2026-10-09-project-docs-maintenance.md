# DR: 项目入口文档随版本与功能同步维护

Status: implemented

## Problem

项目代码已推进到 0.8.8，但 AGENTS.md 与 CLAUDE.md 的版本说明仍停留在 0.7.43。README.md 也缺少新增数据源、原生菜单栏、后台模式和定价交互，部分数据路径与构建命令描述过时，影响用户使用及后续开发定位。

## Decision

[AGENTS.md](../../../AGENTS.md) 与 [CLAUDE.md](../../../CLAUDE.md) 保持相同的完整项目约定，面向开发者和编码代理；[README.md](../../../README.md) 面向用户说明功能、数据来源、安装与构建。三份文档根据当前实现核对，应用版本以 package.json、tauri.conf.json 和 Cargo.toml 为准，依赖版本以锁文件为准。

版本升级时同步三份文档的版本说明，新增数据源、用户功能或开发命令时同步对应章节。保留外部数据库只读和决策记录随非平凡变更提交的约束，明确用量采集、会话元数据与终端恢复的能力边界。

将 [轻量模式审计](../../audits/2026-10-10-lightweight-mode.md) 保存在 docs/audits，入口文档与既有后台模式记录引用已确认的采集和恢复问题，区分代码现状、隔离验证与待修复建议。明确 Cursor 后台只展示缓存、不新增自动 API 请求的约束，保留现有前台 24 小时有效期。

## Alternatives considered

**让 CLAUDE.md 仅链接到 AGENTS.md：** 可以减少重复内容，但依赖读取者继续打开链接才能获得完整项目约定；保留两个入口的同步全文便于各自直接使用。

## Consequences

三个入口反映当前代码，用户能找到新功能和实际数据路径，开发者能按现有契约修改数据源与常驻服务。两个代理入口仍有重复内容，需要在后续版本和功能变更中一起维护；此次只更新文档，不改变应用版本或运行行为。
