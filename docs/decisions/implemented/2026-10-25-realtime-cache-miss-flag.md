# DR: 实时页行级缓存丢失标记

Status: implemented

## Problem

实时请求列表只有页面级「缓存命中率」统计，单条请求是否异常需要逐行口算缓存读与输入的比例，长列表中无法快速定位"花了钱但没省到钱"的请求（缓存被频繁失效、会话每次重算上下文等）。

## Decision

实时页每行按行级命中率 `cache_read / (input + cache_read + cache_write)` 判定（与页面顶部统计同口径），低于 50% 阈值时在模型名右侧显示「缓存丢失」徽标、缓存读 token 染警示色，悬停显示精确百分比与分母构成。两类行不打标：缓存读+缓存写均为 0（模型或数据源不报缓存 token，如 Gemini、GPT 网关、GLM，命中率 0 属正常）；缓存读为 0 且缓存写大于 0（纯缓存写入，多为会话首次请求），后者以中性蓝虚线徽标「缓存新建」弱化区分。阈值 50% 为模块内常量 `CACHE_MISS_THRESHOLD`；警示色使用独立主题变量 `--color-warn`（浅 `#e8590c` / 深 `#ff922b`），与缓存写琥珀 `--color-dark-orange`、费用红 `--color-cost` 区分。仅影响实时页展示，不参与查询、去重与定价口径。

## Alternatives considered

- **行左缘警示色条（含徽标+色条组合）**：真实数据验证后色条被判定为多余视觉噪音，徽标 + 缓存读染色已足以定位异常行。
- **徽标直接显示百分比数字**：更精确但占宽，多数场景只需"正常/异常"二态，精确数值放悬停。
- **阈值做成设置项**：单一合理默认暂无差异化诉求，先常量，有诉求再配置化。
- **无缓存概念行也打标**：Gemini/GPT/GLM 等会整屏误标，标记失去信噪比，故排除。

## Consequences

- 换来：异常缓存行为一眼可见，与页面统计口径一致，不影响落库与跨源去重。
- 代价：每行新增 2–3 次纯内存判定调用（每页 50 行，可忽略）；`--color-warn`/`--color-warn-bg` 需明暗成对维护；调整阈值需改代码重新构建。
- 低命中率不等价于真实缓存失效（短会话、上下文截断也会低命中），徽标是信号不是结论，文案避免"缓存失败"。
