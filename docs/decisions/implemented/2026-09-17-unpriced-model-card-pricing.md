# DR: 未定价模型的卡片展示与原地定价

Status: implemented

## Problem

模型页对"定价表中没有的模型"（自定义 / 中转模型名，如 union-alpha）做了整体短路：卡片只显示"暂无定价数据 + 设置定价"，用量明细（Token、请求数、命中率、费用分解）全部隐藏；页面顶部另有一条横幅提示"N 个模型缺少定价配置"。而那个"设置定价"按钮只做 `router.push({name:'pricing'})`——不带模型定位，也不会打开任何编辑入口。更根本的是，定价页列表完全来自定价引擎（云端定价表 + 已有 override），引擎未收录的模型根本不会出现在列表里，用户跳过去找不到任何可新增的地方。

后端另有一处静默失效：`PricingEngine::refresh` 只用「云端 model_id / 云端别名 / 用户别名」构建别名映射，用户 override 的 model_id 不进映射；而 `get_pricing_at_with_context` 在 `resolve_model_id` 返回 `None` 时直接判定无定价。于是即使把 override 写进 pricing.db，该模型的费用也永远算 0。

## Decision

- 移除模型页顶部的缺定价横幅（`SummaryBar`）。
- 未定价模型的卡片不再短路：用量与费用网格照常渲染，费用按 0 计算；总费用降级为灰色且不可点击对比（0 与 0 对比没有意义）。
- 卡片标题旁新增"缺少定价"标识，复用时段定价徽标的视觉；点击该标识在模型页**原地**打开 `PricingEditDialog`（缺定价以全 0 初值进入），不再跳转定价页。
- 后端 `PricingEngine::refresh` 把用户 override 的 model_id 也注册进别名映射（已存在的映射优先，不抢占云端别名），使未收录模型的定价真正参与费用计算。
- 定价编辑的状态与保存逻辑抽到 `usePricingOverride` composable，定价页与模型页共用；保存 / 恢复后强制重查统计查询（查询结果带参数级缓存，不主动失效会继续显示旧费用）。

## Alternatives considered

- **保留顶部横幅，只修"设置定价"跳转（补 modelId + 定价页新增"待定价"分组并自动展开）** —— 需要给定价页造一批引擎里不存在的虚拟卡片，并维护"用量模型 − 引擎模型"这份集合，改动面最大；而原地定价一旦保存，override 就会进引擎、定价页自然出现该模型，跳转方案的核心价值被抵消。
- **卡片上保留"设置定价"按钮，不另做标识** —— 与已有时段定价徽标的表达方式重复，且卡片高度在有 / 无定价两种状态下不一致。
- **让未定价卡片只显示提示、不给设置入口** —— 用户明确需要一条能真正把定价设上去的路径。
- **彻底删除 unpricedModels / unpriced_models 字段链** —— 移除横幅后它确实没有消费者，但本次改造尚未定型后续是否需要"缺定价模型集合"，先保留以免删了再加。

## Consequences

- 代价：无定价卡片也渲染完整费用网格，视觉上与"真实花费为 0"的模型难以一眼区分，需靠灰色费用 + "缺少定价"标识表达。
- 代价：`refresh` 现在会把 override 的 model_id 注入别名映射；若用户命名与云端别名撞名，仍以云端映射优先（行为不变），但这种冲突不再有任何提示。
- 换来：未定价模型不再丢失用量可见性，"缺少定价 → 原地设置 → 费用生效"形成闭环，且保存后回到列表立即看到重算结果。
