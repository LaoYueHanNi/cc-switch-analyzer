# DR: 模型用量快速带入定价模拟

Status: implemented

## Problem

模型页的用量卡片已经展示输入、输出、缓存读和缓存写四项 token，但用户需要手工切换到定价页并重新填写这些数值，才能用同一组真实用量比较不同模型的费用。

## Decision

模型卡片提供“带入定价”操作，将四项原始 token 通过 Pinia 定价状态发出一次性跨 Tab 交接请求，并跳转到定价页。定价页消费请求后填充四个模拟 token 输入框，各项独立按用量选择 K、M 或 B 显示；请求消费后立即清空，后续用户手工修改不会被旧数据覆盖。

`CompactTokenInput` 与 `useTokenInput` 将实际 token 数和显示值分开保存。带入用量达到 1,000,000,000 token 时显示 B，达到 1,000,000 token 时显示 M，其余显示 K。手工编辑期间保留原始输入文本和当前单位，逐次更新实际 token 数；离开输入框或按 Enter 完成编辑时，达到 1000 K 自动换算为 M，达到 1000 M 自动换算为 B，大数输入或粘贴可以连续进位，不对显示值截断或取整。进入 M 或 B 后继续按当前单位编辑，清空该项时立即恢复 K 并按 0 token 计算，完成编辑后仍保留空输入。显示单位变化不改变费用计算、上下文档位和排序使用的实际 token 数。

## Alternatives considered

**使用路由查询参数传递 token：** 会把完整用量写入 URL，并让刷新、历史导航携带一次性状态，交互语义不够清晰。

**把模拟 token 永久放入全局状态：** 会让用户离开定价页后再次进入时意外恢复旧值，扩大现有定价页状态的生命周期。

**编辑时按阈值同时升降单位：** 用户输入 0.x M 或 0.x B 时会在小数尚未输入完毕前切回更小单位，导致后续输入被按不同单位解释；因此仅在编辑完成时升单位，清空后回归 K。

**逐键或短暂防抖后进位：** 连续输入 1 时，1111 K 被改写为 1.111 M，后续按键就接到小数后面，输入含义发生变化。防抖仍会在用户停顿后继续输入时遇到同一问题，因此用失焦或 Enter 作为完成编辑的明确边界。

## Consequences

四项用量可以从模型卡片直接进入定价模拟，减少重复录入并保留定价页现有的跨模型比较能力。大用量用 M 或 B 展示可减少输入框内的数字长度；单位独立于计算数量，避免 1000 倍的费用误差。交接状态只存在于当前运行会话且只消费一次；刷新应用后不会恢复上次带入的数据。
