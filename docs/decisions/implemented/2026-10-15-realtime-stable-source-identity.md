# DR: 实时请求去重使用稳定的源会话 ID

Status: implemented

## Problem

实时查询在流式去重之后，把 CCS Codex 的逐请求 `session_id` 映射成本机 Codex 真实会话 ID。时间映射缓存有效期为 60 秒，缓存命中时不会补齐新时间戳；因此同一请求可能先返回原始 ID，缓存重建后再返回真实会话 ID。前端每 10 秒使用秒级闭式游标重读最新一秒，把映射后的 `sessionId` 放入去重指纹，导致同一请求在映射变化后再次追加，实时列表和基于列表计算的 Token、费用汇总随之重复。

2026-10-15 的截图中，17:24:08、17:22:49、17:21:52 三组重复展示的记录在 CCS 原始库中各只有一条，均为 `app_type='codex'`、`data_source='proxy'`，并非 Claude Desktop 记录。使用截图中 17:24 请求的时间、Token 和耗时构造轮询回归，旧实现可复现会话 ID 变化导致一条变两条；不同原始请求映射到同一会话时还可能被误去重。

## Decision

- Rust `RealtimeRequestLog` 新增 `source_session_id`，在会话重映射前保留数据源原始 ID，通过 camelCase IPC 返回 `sourceSessionId`；已有 `sessionId` 继续表达会话归属。
- `useRealtimePolling` 的去重指纹使用 `sourceSessionId ?? sessionId`，保留数据源、供应商、秒级时间、模型、四类 Token 与耗时等原有维度。前端字段可选以兼容旧响应；空字符串原始 ID 仍是有效原值，不回退到可变的映射 ID。
- 继续沿用[实时增量闭式游标](2026-08-30-realtime-inclusive-cursor.md)，不改变轮询周期、查询过滤和底层数据。回归测试覆盖映射出现、映射消失、同秒同用量但原始 ID 不同的真实请求，以及单条请求的 Token、费用不重复累计。

## Alternatives considered

- **删除实时侧 Codex 会话映射** —— 当前平铺列表可以不使用映射，但这会改变已有 `sessionId` 的语义。保留归属信息并单独提供原始身份，改动更集中，也允许未来消费会话信息。
- **从指纹移除会话 ID，只比较时间与 Token** —— 能消除本次重复，但会吞掉并行发出的同秒同用量请求，失去原始逐请求 ID 带来的区分能力。
- **只修补时间映射缓存，使新时间戳立即参与映射** —— 可降低映射迟到概率，但本地 JSONL 仍可能晚于 CCS 请求落盘，映射元数据仍会变化，无法保证请求身份稳定。

## Consequences

- 换来：Codex 归属映射变化不再使实时请求列表和顶部用量翻倍，不同原始 ID 的同秒同用量请求仍可分别保留；趋势分析直接从查询管道聚合，不消费此实时列表，本修复不改变其统计。
- 代价：每条实时响应增加一个原始会话 ID 字段，前后端需共同维护身份与归属的区别；原始 ID 本身缺失且其他指纹字段完全相同的不同请求仍有既存误去重边界，本次不扩展所有数据源的请求 ID 协议。
